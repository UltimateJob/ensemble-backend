# 合奏 · 团队使用说明

> 给第一次用这个产品的人。五分钟看完，知道它能干什么、什么时候该用它、什么时候别用。

## 一句话

**一群角色在群里讨论，然后由有权限的那个真的去改代码、跑测试、出文档。**

不是「几个 AI 聊天」，是「讨论 + 执行 + 可回滚」。

## 三种用法

### 1. 直接问（不需要动手）

普通群聊。角色会自己判断该不该接话，没有轮次限制。

适合：想听几个不同视角、需要拆一下问题。

### 2. 代码工作室（会真的改文件）

打开顶栏的 `</>` 按钮 → 选一个本机目录 → 写任务 → 开始执行。

```
工作区：/Users/you/project      ← 点「选择…」或 ⌘O 调原生选择器
权限：命令需批准                 ← 写文件自动，跑命令要你点「允许」
任务：修一下 calc.go 里 Add 的 bug，跑 go test 确认
```

执行时你会看到每一步：读了哪个文件、改了什么、命令输出、diff。**改动可以一键回滚。**

### 3. 群聊协作（讨论 + 分头干）

建一个带权限的群（架构师/前端/后端/测试），把需求发进去：

1. 架构师拆任务、定接口
2. 其余角色认领或提问（「空 name 返回什么？」「并发要不要锁？」）
3. 你确认后，前后端各自开干（scope 不重叠时并行）

## 什么时候该开群（这是重点）

14 个真实案例测出来的，不是感觉：

| 场景 | 建议 | 数据 |
|---|---|---|
| 单文件改动、需求明确 | **单 agent** | 8.0s vs 协作 22.0s |
| 16 文件机械改动 | **单 agent** | 12.1s vs 24.1s，覆盖一样 |
| 修 5 个隐蔽 bug | **单 agent** | 24.1s vs 42.3s，都修了 5/5 |
| 跨前后端、接口要定 | 群聊 | 接口在群里定，比一个 agent 猜稳 |
| 需求本身模糊 | 群聊 | 三人都会追问验收口径 |
| 改动涉及并发/缓存/安全 | 群聊 + QA 审查 | cache-review 里抓到测试旁路 |

**一句话**：协作卖的不是速度，是「有人提问」和「有人回头看」。这两件事不需要时，开群就是白花钱。

完整数据在 [collab-benchmark.md](collab-benchmark.md)。

## 权限

每个角色可以单独设：

| 权限 | 读 | 写工作区 | 跑命令 |
|---|---|---|---|
| `readonly` | ✅ | ❌ | ❌ |
| `approval` | ✅ | ✅ 自动 + diff | 每次要你批准 |
| `full` | ✅ | ✅ 自动 + diff | 直接跑 |

**`full` 等于当前系统用户权限。** 本地运行时不是沙箱——文件工具受工作区限制，但 shell 命令不受。要强隔离得用 Docker/VM（未实现）。

## scope（写入边界）

给角色声明它只能改哪些路径：

```json
{"key":"fe", "permission":"approval", "scope":["web/"]}
{"key":"be", "permission":"approval", "scope":["*.go"]}
```

越界会被服务端拒绝，不是靠提示词：

```
[denied] edit {"path":"main.go"}
   -> 越界：fe 只允许改 web/，不能改 main.go
```

## 能回滚

每次执行前自动做工作区快照。改坏了点「回滚这次改动」，恢复到你按下「开始执行」之前。

并行执行期间回滚会被拒绝——避免连带回滚别人的改动。

## 文档生成

角色可以调 `docx_create` / `xlsx_create` 生成真的 Office 文件（纯标准库，不依赖 Python）。

**数字必须有来源**：文档里写「12 条用例」，这个 12 必须在本次任务的命令输出里出现过，否则被拒。防止编造看起来很专业的数据。

## 已知边界

| 项 | 说明 |
|---|---|
| 本地不是沙箱 | `full` 权限能做当前用户能做的一切 |
| 并行上限 3 个 | 文件级短锁，同时改同一文件会被拒一次 |
| 整文件覆盖风险 | `write` 是「读旧写新」，两个 agent 先后写同一文件时后者会覆盖；`edit` 是安全的 |
| 不支持 pptx | docx / xlsx 已做 |
| 没有云端 Git | 工作区只能是本机目录 |
| 协作不提速 | 见上表，这是实测结论，不是缺陷 |

## 怎么验证没被改坏

```bash
make test        # 单测
make e2e         # 端到端（mock 模式，不需要 Key）
```

跑真实协作对照：

```bash
python3 scripts/collab_demo.py --case demo --root /tmp/ws --task "..."      # 协作
python3 scripts/collab_demo.py --case demo --root /tmp/ws2 --solo --task "..."  # 单 agent
python3 scripts/collab_demo.py --case demo --root /tmp/ws --review --task "..." # 带 QA 审查
```

## 桌面端

```bash
./desktop/build.sh
open desktop/build/Ensemble.app
```

原生窗口（WKWebView，约 200KB，不是 Electron）。⌘O 调本机目录选择器。后端没起来时会自己拉一个。
