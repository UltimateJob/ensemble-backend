# 怎么走查

走查不是测试。

测试验证「点了有反应」，走查问的是**「知道该点哪里」**。

这个项目里走了三次，抓到七个问题，**没有一个能被自动化测试发现**。

---

## 为什么要单独做

E2E 断言的是「元素存在、点了状态变化」。它不会告诉你：

- 空态那行字「点『新建』开一个」旁边没有按钮，用户得自己去右上角找
- 点进随机场景，角色区一片空白，而卡片上写着「开局随机挑 3 个」
- 按钮叫「自己造角色」，点开默认停在「从角色库找」
- 群名弹窗填了默认值，但没说「不改也行」
- 开场结束后焦点在 body 上，想说话得再点一次输入框
- 闲聊群里输入框写「说点什么，或者直接派活…」
- 上手清单里还写着已经改名的「自己造角色」

**这些都不是 bug，是「用起来会卡一下」的地方。** 测试对它们完全无感。

---

## 怎么走

```bash
make run          # 起服务
node scripts/walk.mjs
```

脚本做四件事：

1. 开一个**全新手机号**（已有账号看不到空态）
2. 从登录走到第一次说话，每步把界面上的东西打印出来
3. 每个关键时刻截一张图到 `/tmp/walk-*.png`
4. 不做任何断言——判断留给人

跑完看输出，然后逐条问自己：

```
· 每一步我知道下一步点哪里吗
· 有没有哪个空白让我怀疑「是不是坏了」
· 有没有文案和实际行为对不上
· 有没有需要我猜的地方
```

---

## 走查覆盖的路径

| 步 | 看什么 |
|---|---|
| 1 | 第一次进来：空态有没有出路、引导清不清楚 |
| 2 | 场景页：分区、默认选中、能不能一眼看懂有哪些选择 |
| 3 | 随机场景：角色区空白时有没有解释 |
| 4 | 找角色：搜索入口找不找得到、默认停在哪个 tab |
| 5 | 建群：弹窗问什么、默认值能不能直接用 |
| 6 | 开场的几秒：有没有「正在准备」的反馈 |
| 7 | 轮到用户说话：焦点在哪、提示语合不合适 |

---

## 三条经验

**一、必须用新账号。**

走查的价值全在「第一次」。用已有账号走，看到的是老用户视角，永远发现不了空态问题。

**二、只记「我犹豫了」的地方。**

不要记「这里可以更好看」，要记「我不知道下一步点哪」「我以为它坏了」。前者是审美，后者是障碍。

**三、文案改了要全文搜。**

按钮从「自己造角色」改成「添加角色」之后，上手清单里的同一句话就过时了。改完之后 `grep -rn "旧文案" web/app/`，一处不留。

这一条已经变成 E2E 断言：

```js
ok('界面上没有过时的「自己造角色」文案',
   await cdp.eval('!document.body.textContent.includes("自己造角色")'));
```

---

## 什么时候该重新走

- 改动了**新用户会看到的第一个画面**（空态、场景页、建群流程）
- 加了新的入口（按钮、tab、菜单项）
- 改了任何**文案**

功能越加越多，第一个画面就越容易变得让人迷惑。**改动越多，越要重新走一遍。**
