# 这一轮做完了什么、没做成什么

> 11 轮迭代的收口说明。想上手看 [team-guide.md](team-guide.md)，想看数据看 [collab-benchmark.md](collab-benchmark.md)。

## 一句话

**把「一群角色聊天」做成了「一群角色聊天，然后其中一个真的去改代码」**——并且用 15 个真实案例测了一遍，结论是：**协作不提速，但能让你少犯错**。

## 做成了

| 能力 | 证据 |
|---|---|
| 本地执行器：读写文件、跑命令、快照回滚 | 11 项单测；真实修 bug（5 步 6 次工具） |
| 三档权限 + 服务端强制 | 反例验证：只读角色 `write` 被拒 |
| scope 写入边界 | 反例：`scope=["web/"]` 改 `main.go` → `越界：只允许改 web/` |
| 并行执行（文件级短锁） | 两个 agent 同时改 `main.go`，两行注释都写进去 |
| 审批 once / run | 实测：批准一次后同类命令自动放行 |
| 文档生成 docx / xlsx | `python-docx` 能打开；生成过 2.8KB 周报 |
| 数字来源校验 | 编造的「42 个任务」被拒，agent 改为先 `git rev-list` 取数 |
| 群聊协作（讨论 → 派活） | 讨论 2-3 人接力，执行派给有权限的角色 |
| 原生桌面端 | `.app` 启动截图，⌘O 目录选择器 |
| token 计费 | 修前「单 agent 跑完额度 0」，修后按 token 折算 |

## 没做成（如实）

1. **「1+1 > 2」的效率部分被证伪。**
   同一任务：divide 8s vs 22s、web 6 文件 18s vs 32s、16 文件 12s vs 24s、缺陷修复 24s vs 42s。**单 agent 全部更快，成本低 2-3 倍。**

2. **质量上也没赢。** 缺陷注入实验里，单 agent 和「协作 + QA」都是 5/5。要求单 agent「写完自查」也没有额外收获。

3. **协作会停下来等人。** 模糊需求（「让这个服务更可靠」）下，三个角色都在问「可靠指什么」，零改动；单 agent 直接猜了一个方向改了 4 个文件。

4. **上游不稳定时会卡。** 会话里有 30 分钟是 provider 连续返回空响应，重试耗尽后 goal 被清空——这也是这次会话为什么需要「继承」。

5. pptx、云端 Git workspace 没做。

## 关键结论（有实验支撑）

最后一轮实验把这件事测清楚了：同一个 agent 跑完任务后**自己只读复审**，抓到了主 run 写的 `synctest` 测试根本编译不过（`go.mod` 是 1.21）。

> **1+1 > 2 里的「+1」，是一次独立的验证轮，不是一个并行的脑子。**

- 主 run 38s 交付了坏代码（测试 panic，但它在总结里没说）
- 自查 16s 抓到（换了个上下文，不是换角色）
- 修复 20s 让它真绿

而「写完在同一上下文里自查」没有效果——那等于让模型自己批准自己。

**协作的价值不在「多一个 agent」，在「多一次提问」。**

- 需求模糊时，群聊会先把验收口径问清楚 → 这是真实收益
- 改动涉及并发/缓存/安全时，第二个人读一遍能抓到问题 → 但实测中单 agent 也常能自己发现
- 任务机械、需求清晰时，多一个 agent 只是多一份协调开销

所以产品上的正确默认是：

| 场景 | 用法 |
|---|---|
| 单文件、需求明确 | 直接单 agent |
| 16 个文件机械改 | 直接单 agent |
| 跨前后端、接口要定 | 开群讨论，再派活 |
| 并发/缓存/安全改动 | 开群 + 一轮只读审查 |
| 需求本身模糊 | 开群（但要人在场回答问题） |

## 如果继续做

按性价比：

1. **pptx**（半天）——照 xlsx 的路子，纯增量
2. **云端 Git workspace**（2-3 天）——`Workspace.Source=git` + 远程 runner
3. **让「复审」变成默认步骤**（已验证有效）——主 run → 只读复审（新上下文）→ 修复轮 → 真实测试。成本比开群低，抓到的问题一样
4. **多轮迭代的协作**（现在只测了单轮）——3 轮需求变更下，群聊的记忆和一致性可能才是它真正的主场

第 3 条我认为最值得做：它把协作里唯一被证明有价值的部分（第二双眼睛）抽出来，不付群聊的代价。

## 一句提醒

这套东西的所有边界都是**如实标注**的：`full` 权限等同当前用户、回滚在并行时会被拒、文档数字必须有来源。产品里最危险的不是能力不够，是把「本地运行时」说成「沙箱」。
